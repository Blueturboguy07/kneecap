## Corrections round 3 (2026-08-19, founder's iPhone console log) — fixed in 28e9f2f7 + e7d7a75c

The round-2 UrlSource swap surfaced the layer beneath it ("Retrying failed fetch" spam on merely opening a project):

- **iOS playback URLs were bare filesystem paths.** Swift returns raw `URL.path` values (by design — raw paths are the canonical native handles), but `Capacitor.convertFileSrc` only rewrites `file://`/`content://` strings and passes raw paths through untouched. `toPlaybackUri` now normalizes absolute paths to `file://` first. Android was never affected (`Uri.fromFile(...).toString()`). Verified in-repo that Capacitor 8.5 iOS's WebViewAssetHandler serves `_capacitor_file_` with full Range support (206 + Content-Range), so UrlSource streaming has a sound transport.
- **mediabunny's default retry policy never gives up** on same-origin fetch failures — the infinite loop kept sink-init pending, so the round-2 failed-sink cache/toast never engaged. UrlSource now caps at 3 attempts.
- **CSP listed the wrong iOS origin**: `server.hostname` applies to BOTH platforms, so iOS runs at `capacitor://appassets.androidplatform.net`, while the CSP only allowed Capacitor's default `capacitor://localhost`. Now listed in default-src and img-src.
- **Reopened projects rehydrated dead assets**: storage persisted the zero-byte stub and rebuilt `url` as an object URL of nothing; `MediaAssetData` now persists `url` for native-custody assets (and fps/hasAudio, which were declared but never round-tripped). Assets saved before this fix stay dead — recreate test projects. Known limit: the persisted URI embeds the iOS container UUID → app REINSTALLS orphan saved native assets (v1-acceptable).
- Unexplained log residue to watch next run: one boot-time "JS Eval error", repeated WebKit `AVIF initImage err=-39` decode failures (asset audit pending), and "Updated list with error: DownloadFailed" (believed iOS system noise, not app traffic — the offline gate stays green).

## Round 16 (2026-08-20): the bottom-left-quarter export — the custom compositor never placed its frames

Founder: exported video renders only in the bottom-left fourth of the frame, rest black. Two stacked root causes, both fixed:

- **`EdlTransitionCompositor` composited raw decoded buffers with NO placement.** Custom `AVVideoCompositing` classes receive frames at coded size and AVFoundation applies neither `preferredTransform` nor any fitting — `ciContext.render(image, to: outputBuffer)` drew the source at the output buffer's bottom-left (Core Image's origin) whenever source size ≠ `renderSize`, black elsewhere. A half-size source (proxy fallback, or any canvas/source mismatch) = exactly the bottom-left quarter. Now every source goes through `SourcePlacement` — the Core Image mirror of the preview's `computeVisualTransform`: upright per `EdlAsset.rotationDegrees` (`CIImage.oriented`), contain-fit into `renderSize`, then the EDL clip transform (signed scale, rotation, center offset — the top-left/+Y-down → bottom-left/+Y-up conversion happens ONCE, in `place()`), composited over the EDL background color (flat color parsed, anything else = black). Transitions place BOTH sources before dissolving.
- **`DEFAULT_CANVAS_SIZE` is 1920×1080 landscape, so every phone project was landscape** and a portrait phone video was letterboxed by design even after the fix above. Now CapCut-style aspect adoption: the FIRST visual asset imported into an untouched factory-default project sets the canvas aspect (`getAdoptedCanvasSizeForImportedMedia`, wired at the same `addMediaAsset` seam as the fps ratchet; normalized to the 1080 class, long side capped 1920, even dims, never upscaling small sources). User choices always win (non-default size or `custom` mode → no adoption); rehydration bypasses `addMediaAsset`, so reopening old projects never mutates them.

- **Mobile model (`packages/mobile-ui/src/editor/keyframes.ts`, pure, 19 tests)**: one CapCut "clip keyframe" = one time at which ALL of `transform.positionX/Y`, `transform.scaleX/Y`, `transform.rotate`, `opacity` are keyed, so "on a keyframe", "delete this diamond" and "next keyframe" are unambiguous. Keyframes snap to the project frame grid; "on a keyframe" is a ± half-frame test. Easing presets (Linear / Ease in / Ease out / Ease in & out / Hold) map onto the engine's bezier handles via its own curve bridge and read back through it.
- **UI**: diamond + ‹ › control top-right of the timeline area (the timecode's mirror; `KeyframeControl`), red diamonds at the clip's vertical centre, tap-to-seek onto a diamond, a "Graph" verb on the contextual row once the clip is keyed, and `KeyframeGraphSheet`. Tapping the diamond records the whole group; **CapCut auto-add**: once a clip has a keyframe, a preview drag/pinch or the Overlay panel's opacity slider writes a keyframe at the playhead instead of the base params (preview gesture anchors on the RESOLVED values so a keyed clip is grabbed where it is at that time; captions fan out per target). Live-verified in the vite shell: add → 6 channels at t=0, drag at 1s → second keyframe (284,142) with base params untouched, arrows seek exactly, Graph shows Linear then Ease in & out with handles at 0.42×span, remove → undo restores, opacity slider auto-keys a third diamond, diamond tap lands on 120000 ticks.
- **iOS export**: `KeyframeEvaluator.swift` is a line-for-line port of `interpolation.ts`/`bezier.ts`; `SourcePlacement` carries the clip's visual channels and is resolved ONCE per frame in `EdlTransitionCompositor.startRequest` (main clips' local zero = `ClipPlacement.insertStartTicks`, overlays' = remapped `startTicks`); `containsTweening` is set for animated placements so AVFoundation cannot reuse a composed frame. verify-export-pipeline step 1b checks the port against the engine-generated parity fixture (**162 samples, worst |Δ| 5e-20**); step 13 exports a PiP clip whose positionX is keyframed and a main clip whose opacity fades: PiP band L/R = 129/0 early → 0/130 late, main band 123 → 60. ALL 13 harness checks pass.
- **Android export**: `EdlParser` now parses `animations[]` in full (`EdlAnimationChannel`/`EdlKeyframe`/`EdlCurveHandle`); `KeyframeEvaluator.kt` is the same port, held to the same fixture (`KeyframeEvaluatorTest`, 4/4); `EdlTransformEffect` resolves the transform per `presentationTimeUs`; main-track opacity rides a per-frame `RgbMatrix` (over the black base, RGB×alpha == alpha over black); keyframed PiP alpha rides `CrossfadeCompositorSettings.AnimatedOverlayAlpha` (compositor time base, the one the emulator verified). The composition refuses keyframes on any path other than transform.*/opacity by name instead of refusing all of them. **Honest limit: the Android time base for per-item effects (composition vs item-relative) is asserted, logged on the first frame under `kneecap-export`, and NOT yet run on the emulator** — if a device run shows item-relative timestamps, `itemStartUs = 0` at the call sites is the fix.
- **Cross-language contract**: `packages/editor-core/src/animation/__tests__/fixtures/keyframe-eval-parity.json`, generated by `scripts/generate-keyframe-parity-fixture.ts` and guarded by `keyframe-eval-parity.test.ts` (regenerate when the engine's interpolation changes; both native tests then fail until the ports follow).
